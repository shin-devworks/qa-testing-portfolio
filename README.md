# 🧪 QA / Testing Portfolio

Web・アプリの動作検証、テストケース作成、不具合報告のサンプルをまとめたポートフォリオです。

個人でiOSアプリの企画・開発・実機テスト・App Store公開まで経験しており、その経験を活かしてアプリテスト・QA・開発補助に取り組んでいます。

---

## 👤 About

個人開発したiOSアプリでは、実装だけでなく実機を使用した動作確認、不具合の再現確認、修正後の再テストまで行ってきました。

テストでは「正常に動いたか」だけではなく、

- どのような条件でテストしたか
- どのような操作を行ったか
- 期待する結果は何か
- 実際にどのような結果になったか
- 不具合が発生した場合に再現できるか

を整理して記録することを意識しています。

---

## 🔍 対応可能なテスト

- Webサイト・Webアプリの動作確認
- iOSアプリの実機テスト
- 指定されたテスト項目に基づく検証
- テストケースの作成
- 不具合の再現確認
- 再現手順の整理
- スクリーンショットによるエビデンス取得
- 修正後の再テスト
- テスト結果の整理・報告

## 📋 Test Case Sample

個人開発したiOSアプリ「スキマプラス」を対象として、実際の仕様に基づいたテストケースを作成しています。

主な検証項目：

- タスク登録
- 所要時間の設定
- 優先度の設定
- スキマ時間に応じたタスク提案
- タスク完了処理
- 履歴への記録
- アプリ再起動後のデータ保持

詳細なテストケースは、`test-cases` フォルダに掲載します。

## 🐛 Bug Report Sample

不具合を発見した場合に、第三者が状況を把握・再現しやすい報告を作成することを意識しています。

報告項目の例：

- Bug ID
- タイトル
- テスト環境
- 発生条件
- 再現手順
- 期待結果
- 実際の結果
- 再現率
- 重要度
- スクリーンショット等のEvidence

不具合報告の記載例は、`bug-reports` フォルダに掲載します。

## 🎯 Testing Policy

テスト業務では、以下を大切にしています。

1. 指定された手順・仕様を正確に確認する
2. テスト条件と結果を記録する
3. 不具合発生時は再現性を確認する
4. 第三者が再現できる手順を記載する
5. 必要なEvidenceを残す
6. 修正後は同じ条件で再テストする

「問題があった」という報告だけではなく、開発者が原因を確認しやすい情報を整理して伝えることを目指しています。
